# Published Inventory — Official-Advert Reconciliation

**Audit date:** 2026-10-28  
**Repository baseline:** `d15da0f23fb1ceb7ec90109d75e797c4d3672bf2`  
**Scope:** all records in `data/opportunities.json` at the baseline (17 records).  
**Method:** check primary-source pages/adverts available on the web on the audit date; compare the advertised deadline, identity, application destination and current status against the stored record. A generic careers landing page is not evidence for a specific vacancy, stipend, eligibility rule, or deadline. Search-result absence is not proof that a programme never existed.

## Executive result

- **17 records reviewed**.
- **8 records have a current official advert/page supporting an open application window** at the audit date (IDs 003, 013–019).
- **ID 014 is resolved for publication eligibility by the current official advert image.** The department's 13 October statement reported the original link was dormant and said a correction would follow. The current official vacancy page links to an advert image that contains the corrected Microsoft Forms URL and the 30 October 2026 closing date. The stored URL matches that official advert. This supports an open status as of 28 October, but does not replace end-to-end form testing or monitoring for a newer correction.
- **9 records have passed their stored closing dates and are already flagged expired** (IDs 001, 002, 004, 006–008, 010–012). Their current official career pages do not, in this audit, substantiate the old advert-specific claims. They should remain non-live; the original details and any historic extensions still need archival verification before being represented as fully reconciled.
- The dataset's `verified: true` field is not, by itself, current evidence. It does not encode when or what was verified. Several old records point only to generic careers pages rather than the exact advert.

This is an evidence-based first reconciliation, not a claim that every historical claim (stipend, eligibility, location and advert wording) has been independently re-proven. Keep unresolved records out of the live/open count until evidence is attached.

## Findings and corrections to prioritise

1. **ID 014's original link issue is resolved at the advert level.** The official advert image contains the corrected form URL and the 30 October deadline. The form has not been end-to-end submitted/tested, so retain normal caution and recheck for newer updates. A distinct publication lifecycle field is still useful for future `on_hold`, `withdrawn`, and `needs_review` cases; do not overload `expired` to mean "application link broken".
2. **The nine past-deadline records are not live opportunities.** Their `expired: true` values align with their stored deadlines. However, `verified: true` is stale/ambiguous because the stored source links for these records are generic landing pages and no checked-at timestamp or exact-advert evidence is recorded.
3. **The eight current records with positive primary-source evidence are IDs 003 and 013–019.** This classification means their official source supports an application window as of 28 October 2026; it does not replace field-by-field fact checking or a live test of every third-party form.
4. **Do not count source-page availability as vacancy availability.** A reachable career page without the exact advert is not proof of an open listing.
5. **Evidence model needed:** each record should eventually carry a stable official advert URL, application URL, checked timestamp, verification result/reason, and reviewer/source evidence. Until schema/UI supports this, keep this report as an audit artifact and avoid claiming automated freshness.

## Follow-up work

- **P0:** implement an explicit publication lifecycle state so future records can be held, withdrawn, or sent for review without abusing the `expired` flag; the current official advert image for ID 014 now supports its open status.
- **P0:** add exact advert/evidence links and a checked-at/reviewed-at trail for records 003, 013, 015–019; recheck the application forms before each deadline.
- **P1:** build an evidence register for IDs 001, 002, 004, 006–008, 010–012 from archived official adverts. Keep them expired and do not infer details from current generic careers pages.
- **P1:** add lifecycle states that distinguish open, closing soon, closed/expired, withdrawn, duplicate, and needs manual verification; use the state consistently in UI, counts, static pages and sitemap.
- **P1:** close the separate TVET/jobs metadata gap using the plan in [TVET/jobs metadata gap plan](TVET_JOBS_METADATA_GAP_PLAN.md). Do not add placeholder records to make categories look populated.

## Limitations

This was a web-based evidence pass on 2026-10-28. It did not run the repository's local validators, test the third-party application forms end-to-end, inspect every archived PDF for the nine older records, or independently verify the four individual branch pages beyond the cited employer index and reviewed branch pages. Search indexing may lag; inaccessible/blocked pages should be marked **unverified**, not assumed closed. No published listing data was changed in this audit-only change.
